# Binance Market Monitor

Десктопний застосунок для моніторингу **публічних** маркет-даних Binance за
тикерами монет і токенізованих акцій (bStocks). Читає, рахує й показує —
і більше нічого.

> **Безпека.** Жодних API-ключів. Жодних приватних ключів чи сід-фраз.
> Жодного розміщення ордерів, автоторгівлі чи підключення до акаунта.
> Застосунок показує виміряні числа — рішення ухвалює людина.

## Запуск

Потрібен **Python 3.11+**.

```bash
# 1. (рекомендовано) віртуальне середовище
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 2. залежності
pip install -r requirements.txt

# 3. запуск — підніме сервер на http://127.0.0.1:8787 і відкриє браузер
python -m app
```

Далі у браузері: у полі пошуку введіть назву або тикер (напр. `tesla`, `btc`,
`nvidia`), натисніть **«Додати»**. Символ почне дотягувати 30 днів історії
(видно прогрес backfill), потім оновлюватиметься наживо через WebSocket.
Клік по рядку відкриває деталь: теплокарту й свічки.

Зупинка — `Ctrl+C` у терміналі.

## Перевірка на реальному символі

```bash
python -m app.selfcheck BTCUSDT
python -m app.selfcheck TSLABUSDT
```

Друкує розібраний символ, час останньої закритої свічки, σ, вартість
круговороту на 256 USDT і поточну використану вагу. Ненульовий код при помилці.

## Тести (без мережі)

```bash
pip install pytest
python -m pytest -q
```

П'ять критеріїв приймання: вартість круговороту (959.09 bps на еталонному
стакані), `insufficient_depth`, σ до 1e-9, парсер klines, повторний backfill
без мережевих запитів.

## Пошук за назвою

`exchangeInfo` містить лише тикери, не назви компаній. Тому пошук працює по
підрядку в `symbol`/`baseAsset`, а зіставлення «назва → тикер» ви додаєте руками
у [`aliases.json`](aliases.json):

```json
{ "tesla": "TSLABUSDT", "cerebras": "CBRSBUSDT" }
```

Пошук спершу дивиться в аліаси, потім у тикери. Назви зі сторонніх сервісів не
тягнуться навмисно.

## Налаштування

Значення за замовчуванням — у [`app/config.py`](app/config.py). Щоб змінити, не
чіпаючи код, створіть у корені `config.json` (він не комітиться):

```json
{
  "notional_usdt": 256,
  "hold_seconds": 30,
  "calm_minutes": 5,
  "color_green_max_bps": 20,
  "color_yellow_max_bps": 50,
  "port": 8787
}
```

Абсолютні пороги волатильності ніде не хардкодяться — використовуються лише
перцентилі всередині кожного символу.

## Метрики (усе по закритих 1-хв свічках, відносне — у bps = частка × 10000)

| # | Метрика | Суть |
|---|---|---|
| 1 | Волатильність σ | стд лог-повернень за 60 свічок |
| 2 | Перцентиль σ | де поточна σ у власному розподілі символу (≥30 днів) |
| 3 | Стиснення діапазону | `(max·high − min·low)/median·close` + перцентиль |
| 4 | ATR(14) | True Range (згладжування Уайлдера) / close |
| 5 | Обсяг | останній quoteVolume / медіана 60; флаг `dead_market` нижче 5-го перцентиля |
| 6 | Погодинна сезонність | σ_зараз / медіана σ для (день, година) за Києвом |
| 7 | **Вартість круговороту** | купити N USDT по asks, продати назад по bids; `roundtrip_bps`; `insufficient_depth` якщо глибини мало |
| 8 | Ризик дрейфу | `σ·√(hold/60)·10000·0.8` |
| 9 | Підсумок | `total_bps = roundtrip + drift`, і в USD |
| 10 | Прапорець «спокійно» | усі умови разом, витримані K хвилин поспіль |

## Сповіщення в Telegram

Застосунок може писати в Telegram, коли **обрана** монета входить/виходить зі
стану «спокійно» або коли її `total` падає нижче порога (дешево зайти/вийти).

1. Створіть бота в [@BotFather](https://t.me/BotFather) → `/newbot` → отримаєте
   **токен** виду `123456:AA...`.
2. Дізнайтеся **chat_id**:
   - для особистих: напишіть боту будь-що, тоді відкрийте
     `https://api.telegram.org/bot<ТОКЕН>/getUpdates` і візьміть `chat.id`;
   - для каналу: додайте бота **адміністратором** каналу, `chat_id` — це
     `@назва_каналу` (публічний) або числовий `-100…` (приватний).
3. Задайте змінні оточення й запустіть:

```powershell
# Windows PowerShell (локально)
$env:BMM_TG_TOKEN="123456:AA..."; $env:BMM_TG_CHAT="@my_channel"; python -m app
```
```bash
# Linux/macOS
BMM_TG_TOKEN="123456:AA..." BMM_TG_CHAT="@my_channel" python -m app
```

У шапці має з'явитися **TG ✓**. Кнопка **«Тест TG»** (біля журналу) надішле
пробне повідомлення. Дзвіночок 🔔 у рядку вмикає/вимикає сповіщення для монети.

Поріг «низького total» — `notify_low_total_bps` у `config.json` (за замовчуванням
5 bps; `0` — вимкнути). Вхід/вихід зі «спокою» — `notify_calm_events`.

## Джерела даних і мережа

- REST: `https://api.binance.com`, фолбек-дзеркало `https://data-api.binance.vision`.
- WS: `wss://stream.binance.com:9443`, фолбек `wss://data-stream.binance.vision`.

Клієнт читає `X-MBX-USED-WEIGHT-1M` з кожної відповіді й тримає використання
нижче 80% ліміту; на `429` — бекоф із урахуванням `Retry-After`; на `418`
(IP-бан) — негайно зупиняє запити й показує помилку в UI. При `4xx` від
основного хоста (напр. `451` — гео-обмеження локації) клієнт «липко»
перемикається на дзеркало.

Свічки малюються бібліотекою [lightweight-charts] з CDN; якщо CDN недоступний,
підхоплюється локальна копія з `app/static/vendor/` (застосунок працює офлайн).

[lightweight-charts]: https://github.com/tradingview/lightweight-charts

## Структура

```
app/
  __main__.py    # python -m app → uvicorn + браузер
  server.py      # FastAPI: віддає сторінку + JSON-API
  engine.py      # WS-стрім, перерахунок метрик, стан «спокійно», журнал
  client.py      # httpx-клієнт Binance (вага, бекоф, фолбек)
  backfill.py    # 30 днів 1-хв свічок, без повторних завантажень
  metrics.py     # чисті формули (тестуються без мережі)
  analytics.py   # знімок метрик, сезонність, теплокарта
  db.py          # SQLite (klines/metrics/alerts/watchlist)
  config.py      # параметри
  static/        # index.html + app.js + style.css (vanilla, без збірок)
tests/           # критерії приймання
spike/           # розвідувальний скрипт Кроку 0
aliases.json     # назва → тикер (редагується руками)
```
